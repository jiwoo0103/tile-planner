# Tile Planner

An English tile planning site and an independent project introduction site, both built as static Astro pages. Purchase calculations run in the browser; there is no server API or database.

The [user feedback research handoff](docs/USER_FEEDBACK_RESEARCH.md) records sourced requests for layout and planning features, current coverage, evidence limits, and a suggested order for future work. It is research, not an expansion of the approved roadmap.

## Calculation definition

Required tiles = ceiling of the **unrounded** room area / tile area ratio multiplied by (1 + waste / 100). Base tiles separately round up the area ratio. Boxes round required tiles up to a whole box. Prices are USD per box; tax, shipping, installation and other materials are excluded. This is an area estimate, not a cutting or grout optimization.

Length values use exact rational millimeters internally. Unit selectors only change the display; subsequent calculations retain the exact physical measurements until a field is edited. Display conversions show up to eight decimal places. Bounds are 0.1 mm–1,000 m per room dimension, 0.1 mm–10 m per tile dimension, 0–100% waste, 1–10,000 whole tiles per box, $0–$1,000,000 per box (two decimal places), and at most 10 million required tiles. Invalid edits immediately clear prior results.

Worked examples can open `/calculator/` with query parameters `roomWidth`, `roomLength`, `tileWidth`, `tileLength`, corresponding `roomWidthUnit` / `roomLengthUnit` / `tileWidthUnit` / `tileLengthUnit` (`ft`, `in`, `m`, `cm`, `mm`), `waste`, `tilesPerBox`, and optional `pricePerBox`. Values are validated identically to manual input. Nothing is saved in browser storage.

## Layout definition

`/layout/` accepts the same inputs plus `grout` (millimeters, 0–25 and less than both tile dimensions), `orientation` (`0` or `90`), and `start` (`corner` or `center`). The calculator and layout links carry those values in the URL. Generated links also include bounded `*Exact` rational millimeter values, accepted only when they match the displayed measurement; this preserves unit-switch precision across navigation. Nothing is stored in localStorage.

For one axis of length L, tile size T and joint G, corner placement starts at zero and repeats by T+G, clipping the last piece. If the wall falls in a joint, that trailing grout strip is reported. Centered placement uses N = ceil((L+G)/(T+G)) pieces with equal edge widths E = (L − (N−2)T − (N−1)G)/2 and full interior tiles. If L ≤ T, it uses one piece of length L. An exact fit stays full. Rotating swaps tile width and length. No perimeter movement gap is added.

Geometry counts full tiles and cut pieces separately. These are **not minimum purchasing quantities**: cut reuse and cutting optimization are not modeled. Purchase estimates call the same `calculate()` function as the calculator and do not subtract grout. At more than 2,500 pieces, the SVG only renders the room outline while still showing analytical counts and edge widths. The limit is checked before allocating any tile rectangles. Invalid input clears the previous diagram and summaries.
